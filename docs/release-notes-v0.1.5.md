# v0.1.5

统一为无历史兼容路径的当前实现，删除数据库迁移与旧字段回退，并收紧价格快照校验。
宿主要求为 **CLIProxyAPI v8.0.30、ABI 1 / RPC schema 6**。

## 部署前必读

1. **本版不支持从 v0.1.4 或更早版本原地升级。**
   首次部署必须使用新的空 `data_dir`。旧账本、Key 和定价不会自动迁移或导入。
   如需保留旧记录，先停止 CPA，冷备整个旧 `data_dir`，将其作为独立档案保留；
   不要删除旧数据，也不要只替换旧目录中的数据库文件。
2. 账本一次性创建完整 schema，并以 `PRAGMA user_version = 1` 标记当前格式。
   非空且没有当前格式标记的账本、其他版本账本均拒绝打开；
   插件不会迁移、清空或自动修复它们。
3. **保留发布库文件名 `cliproxyapi-credit-manager.so` / `.dylib`。**
   不匹配的插件实例 ID 会停止新请求准入，避免执行后无法归属用量。
   RPC schema 低于 6 的宿主直接拒绝注册，不再向下协商。
4. 继续保留至少一把从未分发给客户的 CPA 原生守卫 Key。
   客户 Key 只存于本插件；不要向客户分发可绕过计费的原生 Key。

## 实现精简

- 删除历史表结构迁移、旧预占列清理、HMAC-only Key 兼容与旧价格字段重建。
- Key 必须包含 AES-256-GCM 加密材料；查看失败时拒绝返回伪造或回退的明文。
  数据库与 `pepper` 必须一并保护和备份。
- 请求只以必填的 `price_snapshot` 保存冻结定价，不再复制旧费率列。
  基础费率和档位费率字段缺失、为 null 或不合法时拒绝读取和结算；
  完整且明确配置为零的基础费率仍表示免费。
- 首次准入、幂等重放和后续读取返回相同的冻结定价元数据，
  包括规则 ID、档位、服务等级和请求图片数。
- RequestedModel 必填；计费不回退到执行模型或响应模型。

## 界面与契约

- 管理端和客户页只消费当前 snake_case API 字段，不再读取旧 token、
  缓存或额度字段别名。
- 额度展示使用 `quota_used_micro_usd`，不以历史累计消费代替重置后的额度基线。
- TPS 仅使用与有效延迟成对的 `measured_output_tokens`，不混入未测量输出。
- 删除不支持的概览来源控件及旧版 Key 冲突提示。
  金额仍以整数 microUSD 在 API、表单、图表提示和客户查询间无损传递。

## 保持不变的边界

- 不预估或预占金额/token。正数剩余额度允许请求；实际已用达到限制后拒绝后续请求。
  已放行及并发请求可能超额，可靠实际用量仍足额记账，不截断费用。
- 不接管 Executor、Router 或 Scheduler。
  执行、上游账号选择、重试、故障转移和会话亲和仍由 CPA 管理。
- 未知用量保持 `pending`，不伪造免费结算。
  CPA 内存用量队列不提供宿主崩溃后的零丢失或端到端 exactly-once 保证。

操作与恢复边界见[运维文档](https://github.com/fengwk/cliproxyapi-credit-manager/blob/v0.1.5/docs/operations.md)。
