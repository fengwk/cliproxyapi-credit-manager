# v0.1.4

移除预算预占，按实际用量记账，并恢复不接管 CPA 执行链的管理、定价与分析功能。
宿主要求仍为 **CLIProxyAPI v8.0.30、ABI 1 / RPC schema 6**。

## 升级前必读

1. **先停止 CPA，冷备整个 `data_dir`**，尤其是配套的 `credit.db`、WAL 与 `pepper`。
   启动时会事务化升级到 schema v2，删除旧预占/估算列，保留实际扣费、Key、价格、
   请求、用量、人工调整、审计和重置基线。迁移幂等，失败整体回滚。
   **不支持直接降级**；需要回退时须还原升级前的冷备。
2. **删除旧配置 `warmup` 和 `max_pending_requests`**，包括 `warmup: {enabled: false}`。
   这些字段不再受支持，保留会导致插件注册失败。CPA 配置保存接口返回 200
   不代表随后重载成功；宿主完整重载可能先卸载旧实例，不能依赖旧配置继续服务。
3. **额度现在是软准入限制，不是防透支的硬上限**。准入只检查实际已用额度，
   不估算请求金额或在途 token。实际已用达到正数限制后，拒绝下一次请求；
   并发、流式与已放行请求可能超额，可靠实际用量仍足额入账，不截断费用。
4. 保留至少一把从未向客户分发的 CPA 原生守卫 Key，客户 Key 仅存于本插件。
   原生 Key 列表为空可能放行匿名请求，向客户分发原生 Key 则可能绕过插件计费。

## 架构精简

- 删除金额/token 预估、预占、预算释放与恢复逻辑，以及 API 和界面中的预占字段。
- 删除未决请求积压闸门。未知用量仍可见为 `pending`，不伪造免费结算，
  但不冻结预算，也不通过独立积压限制阻塞后续准入。
- 删除后台账号预热、宿主模型执行桥及相关暂停/排空状态。
- 删除全局财务故障锁。准入因自身校验或存储错误失败；
  用量、完成及维护错误通过健康状态报告，不永久阻断所有 Key。
- 保留必要的 SQLite 账本、保留期内幂等、请求/Key/Trace 关联、当次费率快照、
  显式 Key 并发限制、历史清理及安全卸载同步。
- 不注册 Executor、Router 或 Scheduler；上游账号选择、重试、故障转移和会话亲和仍归 CPA。

## 管理与定价

- 新建或轮换的客户端 Key 使用 AES-256-GCM 保存可恢复密文，支持显式查看并记录审计；
  旧 HMAC-only Key 无法恢复明文，需要轮换。密文和 `pepper` 必须一并保护。
- 支持调用方归属元数据、Key 软删除、总/日/周/月额度及模型 token 基线重置。
  重置不删除历史或实际累计消费，已放行请求的迟到用量仍会记账。
- 支持 exact/glob/regexp 定价规则、确定性优先级、上下文/服务档位及按图计费。
  准入冻结完整定价决定，后续改价不追溯修改旧请求。
- 显式零基础费率表示免费；缺失价格或禁用的获胜规则拒绝请求。
  金额保持整数 microUSD，实际 token 费用精确求和后只向上取整一次。
- 模型目录与 USD/CNY 汇率为只读参考数据，采用有界缓存并拒绝 HTTP 重定向。
  导入价格必须明确确认，不会后台自动改价。

## 界面与查询

- 恢复 CPA 风格主题、紧凑响应式布局、登录会话保持与显式记住密钥。
- 新增全量筛选集的模型占比、效率排行及请求/token/费用趋势，不以当前页冒充全量。
- 恢复客户自助额度、用量、趋势与请求快照查询，保持 Key 归属隔离。
- 金额与大整数在 API、表单、图表提示和客户查询中保持无损处理。

## 保证边界与验证

- CPA 用量投递队列仅在内存中；本插件不承诺宿主崩溃时事件不丢失，
  也不承诺端到端崩溃安全 exactly-once。未知账务须通过 `pending` 和人工裁决核对。
- CPA SDK 未提供实际出图数；按图计费仅在成功且计量可信时，
  按冻结的请求图片数计一次。默认 1 张，显式只支持 1..32 张，越界拒绝而不截断。
- Go vet、8 个 Go 包单元及 race 测试、122 项 Node 测试、125 项静态检查通过。
- 管理端浏览器 285 项、客户查询浏览器 89 项、CPA v8.0.30 原生验收 65 项通过。
  原生验收使用真实宿主与插件库、环回合成上游，不接触生产凭据。
