# v0.1.2

全仓审查后的正确性与隐私修复，建议 v0.1.0 / v0.1.1 用户升级。
宿主要求仍为 **CLIProxyAPI v8.0.30、ABI 1 / RPC schema 6**，不新增依赖、不变更财务 schema。

## 计费与财务边界

- 修复上游账号的 Source 标签为 `internal`、`warmup`、`plugin_host_model_callback` 等时，
  正常客户用量被误判为内部活动而跳过计费的问题。Source 不是可信执行来源；
  客户归属以宿主解析的本插件 AccessProvider 和已预留请求为准。
- 修复省略时间戳的相同用量回放被适配层补上不同当前时间、进而产生冲突的问题。
  结算前后回放保持幂等，不重复扣费或恢复金额占用。
- 显式 Key 过期时间必须能精确往返 int64 Unix 纳秒；拒绝溢出时间和会变成不限期的
  year 0001 零值。只有 `null` / 未设置才表示不限期。
- 拒绝空或首尾带空白的 `data_dir`，不再静默裁剪并打开不同的账本目录；路径内部空格仍合法。
- 拒绝报表分页偏移及时间范围溢出，避免静默返回第一页或错误日期区间。

## 请求快照隐私与资源限制

- 修复重复 JSON 键覆盖 secret 后，原始含 secret 正文可能被误认为无需脱敏而落盘的问题。
  在完整解码前拒绝重复键，包括转义后等价的键（例如 `"x"` 与 `"\u0078"`）。
- JSON 结构预检限制为 **256 层、100,000 节点**（键和值均计数），防止体积合规但
  高复杂度的正文构建巨大的对象图；拒绝时只丢弃诊断快照，不影响推理和财务。
- 超过 **128 UTF-8 字节**的请求 ID 不进入状态环或快照库，只增加 dropped 计数。
- 清理/淘汰保留状态证据时不再改写原快照过期时间；证据有独立的有限保留期。
- 捕获仍默认关闭，只针对已知敏感字段脱敏；非 JSON 正文仍可能原文保存，**不是全面 DLP**。

## 管理界面

- 当前 USD 输入非法时阻止提交，不再沿用之前换算残留的微美元金额。
  覆盖财务裁决、Key 额度及模型价格；可选思考单价只有两个输入框都为空才回退到输出价。
- 会话切换作废旧响应及旧错误，防止旧 401 踢掉新会话、旧请求回填账务或弹出明文密钥。
- 资源查询按最新意图更新，切回缓存同样作废在途旧查询，迟到成功/失败不能覆盖当前结果。
- 自定义 Key 创建/轮换原样提交，不做 trim；仅真实空值请求服务端生成，编辑不回传材料。
- 创建/保存/轮换进行中阻止重复提交；旧弹窗失败不会解除新弹窗的提交保护。
- 捕获状态中文标签与服务端实际取值一致。

## 回归与交付

- 新增有修复前失败证据的单元、受控异步浏览器与真实 CPA 回归。
- 审查候选验证：Go 184 个顶层测试及 24 个子测试、race、Node 34 项、
  Chrome 192 项、真实 CPA 14 模块 42 项全部通过。
- 验收工具修复恒真断言、浏览器启动失败后的 Playwright 清理和 Chrome profile 清理竞态；
  新增 4 项 Python 生命周期回归，支持显式 `CHROME_BIN`，不做隐式浏览器 fallback。
- 提供 Linux amd64、Linux arm64、macOS arm64 原生库和 SHA256 清单。

## 升级与历史数据

1. 停止 CPA，备份整个插件数据目录（`credit.db` 与匹配的 `pepper` 必须一起保留）。
2. 校验下载归档的 SHA256，替换同名动态库，保留原数据目录及原有客户端 Key。
3. 检查 `data_dir` 不带首尾空白，重新启动并确认 health、账本和请求结算。

本补丁不推测或追溯改写历史数据。若旧版本存在上述 Source 标签碰撞，请检查受影响的
pending 请求并按实际凭证核账；若曾配置越界过期时间，也应核对受影响 Key 的实际限制。
旧版本已经保存的快照不会自动重新脱敏；如怀疑包含敏感数据，应在停机后清理可丢弃的
快照数据并评估密钥轮换，**不要为此删除财务账本或 pepper**。

CPA 用量投递非持久、预授权不是最终账单硬上限、单目录单实例及守卫 Key 部署要求不变。
完整安装、安全边界与运维说明见 [README](../README.md) 和 [运维手册](operations.md)。
